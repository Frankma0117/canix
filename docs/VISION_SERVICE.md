# Vision service (Fashion Mode)

A separate Python microservice (`vision-service/`) that classifies garment photos with a CLIP model
(zero-shot, free, runs on the same server) and extracts the images of a PDF. If it isn't running,
Fashion Mode asks to classify the garment by hand - it never blocks the bot.

It is a separate process because running a vision model inside Node would bring back the native
binary problems `better-sqlite3` already had on these machines; Python gets its own venv, and if
the service crashes the bot keeps working.

When `FAL_KEY` is set, a vision LLM (`services/fashion/vision/llm-vision.service.ts`) classifies
instead, looking at the photo and leaving questions in the portal for what it is unsure about. This
service is then still used for PDF extraction.

## Run it

- **Windows (local):** `vision-service\dev.cmd` - creates the venv the first time, installs
  dependencies, starts uvicorn with reload on `http://127.0.0.1:8008`.
- **Server:** `deploy/ubuntu-05-setup-vision.sh` then `sudo deploy/ubuntu-06-setup-vision-service.sh`
  (systemd unit `canix-vision`; `./deploy.sh` runs both).
- **Manual:**

  ```bash
  cd vision-service
  python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
  pip install -r requirements.txt
  uvicorn app:app --host 127.0.0.1 --port 8008
  ```

The first start downloads `patrickjohncyh/fashion-clip` (~300-400 MB) from Hugging Face and caches
it; if that fails it falls back to `openai/clip-vit-base-patch32`. `VISION_MODEL_NAME` picks another
model. It listens on localhost only; the bot reaches it through `FASHION_VISION_SERVICE_URL`.

## RAM - check on the real server

It is not guaranteed to fit comfortably on a 4 GB server shared with the bot, ffmpeg and Vosk.
Before `FASHION_MODE_ENABLED=true` in production: start it, wait for "Vision model ready.", run
`free -h`, send a couple of real photos, run `free -h` again. With less than ~300-500 MB free:
keep `OMP_NUM_THREADS=1` (already in the unit), try a lighter model, add swap as a stopgap, or run
Fashion Mode without automatic classification.

## Endpoints

- `GET /health` → `{"ok": true, "model_ready": true}`.
- `POST /analyze` (multipart): `image` (file) and `labels` - JSON with the candidate taxonomy,
  `[{"group":"type","values":["TOP","BOTTOM",...]}]`, generated by the bot from
  `backend/src/services/fashion/taxonomy.ts` on every call (the service keeps no copy, so they never
  drift). Answers only with values from those lists, with a confidence per group, plus photo
  quality issues (blur, darkness…) and the model name for traceability.
- `POST /extract-pdf` (multipart): `file` (PDF) and optional `max_images` (default 15). Returns
  `{"images": ["<base64 jpeg>", ...], "totalFound": N}` (`totalFound` counts before the cap). Only
  images embedded in the PDF are extracted (pages are not rendered); exact duplicates and images
  under 150 px are dropped. Uses PyMuPDF only - no model involved.
